내 PC에서 접속

포털 http://prismjuns ↗ERPNext http://prismjuns:8080 ↗

같은 PC에서는 http://localhost와 http://localhost:8080도 사용할 수 있습니다. 포털은 http://prismjuns:3000으로도 접속할 수 있습니다.

Windows가 접속 포트를 받고 WSL의 로컬 포트로 전달합니다. 자기 PC와 사내망 기기에서 같은 주소를 사용할 수 있습니다.

같은 사내망의 다른 PC · 휴대폰

다른 기기에서 접속

포털 http://192.168.123.66 ↗ERPNext http://192.168.123.66:8080 ↗

기기에서 이름을 찾을 수 있으면 http://prismjuns도 됩니다. 이름 해석이 안 되면 위 IPv4 주소를 사용하세요. 포털은 http://192.168.123.66:3000도 됩니다.

Windows·WSL 방화벽은 해당 사내망의 TCP 80·3000·8080을 허용합니다. DB 포트는 외부에 공개하지 않습니다. 인터넷 공개 주소는 아직 없습니다.

배포 직후 사내 접속 계획

  • 포털http://prismdev 또는 http://192.168.123.52
  • ERPNext별도 호스트명 또는 포트를 배포 시 확정합니다. 개발의 8080을 서버가 이미 사용한다는 뜻은 아닙니다.
  • 상시 운영로그인·권한, 재시작 정책, DB·첨부파일 백업·복구를 검증한 뒤 실제 업무 데이터를 사용합니다.

정식 운영 주소

선택한 도메인의 HTTPS 주소를 공통 프록시로 연결합니다. 포털과 ERPNext의 호스트명·인증서·외부 접속 방식은 배포 단계에서 정합니다.

운영 코드는 이미지에 포함하고, 서버의 DB와 비밀 설정은 개발 PC와 별도로 둡니다. WSL 개발 DB를 서버에 덮어쓰지 않습니다.

make deploy REV=<커밋>은 아직 구현 전입니다. 현재 scripts/dev.py는 운영 서버 실행·초기화를 거부합니다.

04 / CONNECTION CHECK

접속이 안 될 때, 이 순서로.

  1. 접속 대상 확인

    개발은 prismjuns, 운영은 prismdev입니다. 다른 PC에서 localhost를 쓰고 있지 않은지 확인하세요.

  2. 앱 실행 확인

    WSL에서 make ps. 필요하면 make dev 또는 make erp-demo. PC가 절전 상태인지도 확인합니다.

  3. 이름 대신 IP 사용

    개발 포털은 http://192.168.123.66. IP는 되는데 이름만 안 되면 DNS/hosts 문제입니다. 공유기에서 IP가 바뀌면 이 안내와 개발 호스트 설정도 갱신해야 합니다.

  4. 같은 네트워크인지 확인

    같은 사내망에 연결하세요. 게스트 Wi-Fi의 기기 격리나 VPN, 방화벽이 연결을 막을 수 있습니다. 재설정 절차는 scripts/windows/enable-dev-lan.ps1에 있습니다.

  5. 앱 응답과 로그 확인

    포털 /api/health, ERPNext :8080/api/method/ping을 확인합니다. 접속 문제를 해결하기 위해 DB를 초기화할 필요는 없습니다.
